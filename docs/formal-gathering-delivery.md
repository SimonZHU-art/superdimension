# 正式主题聚会与主岛档案 · v0.14

本轮把 v0.13 的可行走交流场景、授权资料分析、私人发现、建议草稿和档案交付接到主岛的正式存档。生产环境开放，不依赖 NODE_ENV=development，也不调用 /api/gathering-demo。开发隔离仍保留。

## 使用

岛主登录，到北岸船台。造好船后填写主题、场景、120／180 分钟时长、助理功能和本次私人关注方向，选择「创建主题聚会并出航」。当前画面和控制就绪后才开始服务器共同倒计时。打开「聚会与助理」可复制邀请。

来客通过该邀请进入，可只填昵称，也可填写简介、作品和交流偏好，上传 TXT／MD／PDF／DOCX 简历（最多 2 MB、14,000 字符；PDF 最多 20 页，需要可提取文字）。文件只解析为正文，未选择分享的内容不进入交流授权。

每位真人分别操作自己的角色。走近另一人按 E 或点击其角色发起邀请；双方确认才保存本次开放资料的固定版本并启动助理。对话由参与者本人发送。助理使用主岛当前配置的真实模型和自己的主人上下文；私人关注、报告和发现不进入另一方的资料包或消息。建议只追加到可编辑草稿，仍由本人点击发送。

「准备虚拟来客并远航」是可选演练：资料和固定回复由岛主设定，当前真实模型处理资料，演练札记保存在主岛并标明虚拟来客；不会伪造真人登记。默认不携带该虚拟角色的私人助理，也不创建假主岛身份。

真人和虚拟来客共用正式领域模块。随行助理只携带功能，场景不增加助理人物贴图。远端角色按收到的位置连续走动，虚拟来客轻度漫游；暂时离线的真人不持续留作静止人物。

举办者返航／到期结束整个聚会；来客返航只离开自身。已接受任务继续处理固定输入。正式船只按原规则结算为破损，修缮消耗 20 木料；来客不消耗造船材料。独自探索保留原有不损船流程。

成果可在「我的岛屿 → 聚会档案」和档案官／策展人／研究员／联络官对应书桌阅读，包含原始授权资料、对话、来源、报告及历史资料版本。档案不会伪装成原来的阿斯伽德真人登记记录。

## 实现与当前边界

server/gatheringProduct.mjs 把 cookie 验证后的身份、当前船只库存、Gatherings 领域服务、既有真实模型管线与主岛 SQLite 连接。服务器每秒调度过期与待处理任务，最多两项模型任务并发；交流内容每 30 秒合批。任务额度为每个成员每场 24 项，失败可以按原资料单独重试。重启恢复未完成任务与共同期限；仍只支持单服务实例的 SQLite。

正式接口不接受客户端伪造 A／B 或岛主身份，也没有推进时钟、模拟失败或测试物资接口。来客撤回原游客资料时，相关主题交流、输入、派生任务和档案同时移除；处理中模型返回不会复活已删除资料。

当前最多 16 名成员，位置与消息约 1.6 秒快照同步，没有 WebSocket；极短尚未保存的移动可能回退。支持同一服务上的岛主与游客；其他独立部署的岛主还不能携带其私有上下文跨服务互通。复制的邀请必须使用别人可以访问的主岛网址：localhost／127.0.0.1 只能在本机打开，互联网分享仍需要当前可用的临时隧道或正式部署。

## 验证

最终完整回归 146 项通过，生产构建通过。新增覆盖正式模式开放、真实库存预留与一次船损、两个独立游客会话、明确授权／拒绝、真人消息与固定虚拟回复、本人报告隔离、SQLite 重启恢复、上传解析、资料撤回及处理中删除。所有自动模型输出都来自明确的 TEST FIXTURE，没有调用真实 DeepSeek 或发送邮件。

实际页面另在生产模式、独立临时 SQLite 和明确的合成资料上完成：创建聚会、复制邀请、第二角色填资料／加入、双方接受、双向消息、私人发现、刷新恢复、返航以及主岛书桌读取成果。证据位于 docs/proofs-v15。页面中的 TEST FIXTURE 是验收替身，不能作为真实模型质量证明。

主岛服务使用原 .env 和原数据路径；部署前通过 SQLite backup 保存一致快照到被 Git 忽略的 .data/backups。没有向真实存档注入合成人物或测试材料。
