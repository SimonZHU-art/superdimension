# v0.15 · 一边交流，一边听随行居民介绍来客

2026-10-10

## 体验方式

北岸「开发隔离」和正式「准备虚拟来客并远航」共用随行圆桌。在主题岛走近来客并按 E，双方确认后，自己的助理开始处理本次开放的材料。圆桌直接显示每位助理的等待、阅读、交付或失败状态，并按职责轮流介绍；可以暂停、选择另一位或收起圆桌继续探索。

- Doctor Strange：身份、当前工作、代表经历、可追溯能力与资料缺口。
- 黄四郎：具体项目与作品、本人负责的工作、已有产出、为什么值得先聊。
- 纳德：项目方法、结果、样本与限制；未配置个人专题时先核对基础项目资料，不假称已经找到专项匹配。
- 混子（本次选中时）：值得继续聊的共同话题、待确认问题与交流顺序。

每份介绍包含原始发现、可打开的对应原文，以及能放进聊天草稿的具体问题。问题只追加，不自动发送。较长的介绍默认折叠；阅读原文或选择居民会暂停自动轮流播放。继续聊天形成新版本；新资料处理中仍可读上一份已交付介绍。已重试成功的旧失败不再影响最新处理状态。

## 实际资料处理

PDF/DOCX 沿用原解析器。简历正文拆成保留原文的可读段落，而非把整份 PDF 当成一个引用。引用按交流、接收者、资料版本标识，在本人不同角色间保持一致；每条事实可追到同一次授权的原段落。主人的提问不能单独充当来客履历事实，模型引用不存在的段落仍会失败并保留可重试状态。

有模型配置时，开发准备窗口默认选择当前真实模型；未配置时使用明确标注的本地原文摘录。离线摘录按职责选取身份、项目、方法等内容，跳过“见简历”等占位正文，保留原文与来源，不伪装成模型推理。保存的 B 资料会恢复到准备窗口，继续沿用上传的 PDF 正文。

自己的档案官先整理同一份获准输入；其他角色实际参考本人、同一交流、同一版本的已完成档案，同时继续核对共同原文。档案官失败时其他角色仍可独立阅读原文。界面中的“已参考同版档案”来自实际处理记录，不是虚构动画或其他人的私人报告。

此版本没有来客侧的真实 A2A 通道。开发选项里的 B 私人收件箱是独立测试处理，不冒充真人 Agent 对话；虚拟 B 仍按用户预设的固定内容回复。不会据此编造项目、承诺或新立场。随行助理只在圆桌中显示头像与发言，地图不增加实体角色。

## 存档与验证

两种玩法共用显示与真实处理逻辑，正式玩法继续使用原 SQLite、授权快照和原有返航规则；开发模拟交流仍在独立内存工作区，准备资料保存到其所在服务的数据库。正式主岛、试玩主岛和开发隔离档案保持既有范围。两个后台同步更新，既有配置、资料、物资和正在进行的正式聚会保留；更新前保存了数据库备份。

自动化覆盖原文分段无丢失、角色间引用一致、跳过文档前言并提炼项目、不能把主人的问题写入来客履历、资料版本更新时保留旧成果、同侧同版协作、失败降级、建议只追加且不发送，以及虚拟问题与固定回复成对处理。

本机实际使用既有 DeepSeek 配置，处理用户上传的《周屿_虚拟人物档案_扩展版.pdf》及四条获准对话，交付了档案官、策展人和专项研究员的带来源汇报。提炼内容包括校园旧物信息页改版、家居商品详情页改版、促销检查流程的本人职责和结果限制。该文件为用户提供的虚构人物设定；实测说明模型确实处理了该材料，不说明人物履历已在现实中核实。

完整回归：153 项通过；生产构建成功，无警告。实际浏览器验证处理状态、角色切换、对应原文、建议保留原草稿且未发送，未发现浏览器运行错误。
