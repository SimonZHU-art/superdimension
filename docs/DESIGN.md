# 云汀小镇：实施美术方案

依据：MVP v0.3 的暖色、原创像素感 2D、斜俯视、桌面优先。此文是实施方案，不扩展产品范围。

## 画面与布局

第一眼看到可行走的小镇。岛屿、水岸、树木和六个居民占据主画面；操作提示、时间与声音控件贴边排列。登记、报告和联系在玩家接近对应建筑后打开可读的 HTML 面板。世界承担空间与情绪，面板承担真实资料的阅读。

```text
┌ 小镇名称／时间                         声音／岛主入口 ┐
│                                                   │
│       档案馆       广场      策展屋                   │
│             居民与玩家                              │
│       海关         桥       邮局／会议室             │
│                    河岸与树木                       │
└ 移动与交互提示                    当前可触发的动作 ┘
```

世界元素采用有限色块、阶梯轮廓、像素描边和一致光向。建筑外观通过屋顶、门牌和工作道具区别职能。不要让建筑仅成为六张相同的卡片。层级按地面、植被、角色脚点、建筑前景排序；角色移动受水岸和建筑碰撞约束。

## 颜色

| Token | 值 | 用途 |
|---|---|---|
| Parchment | `#fff0d2` | 面板纸面、轻量提示 |
| Ink | `#49372e` | 正文、描边、木结构 |
| Cedar | `#496644` | 树叶暗面、可行走空间边界 |
| Sage | `#91ad6b` | 草地、浅色植被 |
| Water | `#65a6a5` | 河流与水岸 |
| Roof | `#b96b50` | 屋顶、陶土工作道具 |

金色 `#dfb257` 仅用于交互提示与待查看成果；黄昏 `#535d79` 通过世界光色表达时间，不降低面板正文对比度。主屋使用灰蓝屋顶 `#657c80`，与陶土色工坊区分。失败、处理中、成功同时使用文字和图标，不仅靠颜色。

## 字体与可读性

中文正文使用系统可用的 PingFang SC / Microsoft YaHei；标题可使用宋体家族增加小镇书册感。像素感留在世界资产与有限的短标签，不用于长篇报告。正文 15–16 px、行高 1.6–1.75；面板标题 23–28 px，次标题 18–20 px。报告保持左对齐、段落宽度约 30–42 个汉字；状态与来源标签允许换行。

## 原创生活与真实状态

六个角色是主 Agent、海关、档案官、策展人、联络官和一个可配置专项角色。每个角色有独特服饰、名字和站位；生活日程与短故事由程序控制。风、水、灯光、走动和三处可触发环境互动使无人登记的小镇成立。

工作中、完成、失败由服务端任务状态决定；动画不能伪装处理完成。虚构剧情与真实访客资料分别保存。兼容外部身份包控制投影外观；缺少兼容形象时清楚标记通用形象。

## 交互原则

- WASD / 方向键移动，E 或对应按钮交互；聚焦输入框时暂停世界快捷键。
- 开放游览是默认状态。自愿登记在海关完成，允许离开面板继续探索。
- Escape 关闭面板；按钮有可见键盘焦点，弹层标题和关闭动作明确。
- 声音在用户交互后启动，并支持静音和音量；减少动态偏好限制装饰性运动。
- 窄屏给出桌面体验提示，同时保留公开介绍与必要导航。
- 联系发送前完整呈现收件人、主题、正文和随附资料；模型和邮件未配置时如实说明。

## 本轮自评

暖色来自屋顶、草地和水岸的具体材质，第一屏的主角是城邑。面板是纸质工作台的阅读延伸，避免统一卡片网格和营销首页结构。后续视觉验证需检查碰撞、建筑入口、NPC 可识别性、弹层长文、键盘操作、昼夜和窄屏；当前设计文档不代表视觉验收已通过。
